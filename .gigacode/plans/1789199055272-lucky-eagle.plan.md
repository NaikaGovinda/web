# План: Web Push Уведомления из браузера

## Цель
Добавить веб-уведомления (push из браузера), которые дублируют функционал Android-уведомлений. При создании уведомления в системе — браузерные пользователи также получают push-уведомления с deep linking на нужную страницу.

## Подход
Используем **FCM для Web Push** (тот же проект, что и для Android). Service Worker обрабатывает push-события, браузерный Notification API показывает уведомления.

---

## Фаза 1: База данных

### 1.1. Новая таблица `user_web_push_subscriptions`
**Файл:** `migrations/002_create_web_push_subscriptions.sql`

Поля: `id`, `user_id`, `endpoint`, `p256dh`, `auth`, `browser`, `active`, `created_at`, `updated_at`
- `endpoint` — уникальный ключ (каждая подписка уникальна)
- `active` — soft delete (как в `user_fcm_tokens`)
- Foreign key на `users(id)` с CASCADE

---

## Фаза 2: Backend API (новые файлы)

### 2.1. `api/save_web_push_subscription.php`
- POST: `{ endpoint, p256dh, auth }`
- Session auth (`$_SESSION['user_id']`)
- INSERT ... ON DUPLICATE KEY UPDATE
- Detect browser из User-Agent

### 2.2. `api/remove_web_push_subscription.php`
- POST: `{ endpoint }`
- Sets `active = 0`

### 2.3. `api/send_web_push.php`
- Функция `sendWebPushToUser($pdo, $userId, $title, $body, $data)`
- SELECT активных подписок из `user_web_push_subscriptions`
- Для каждой — HTTP POST к FCM endpoint (JWT OAuth2 из `send_fcm.php`)
- На 410 Gone — soft-delete подписки

### 2.4. `api/get_vapid_key.php`
- Возвращает VAPID public key для frontend подписки

---

## Фаза 3: Frontend (новые файлы)

### 3.1. `service-worker.js`
- `install` → `skipWaiting()`
- `activate` → `clients.claim()`
- `push` → парсим JSON, показываем `self.registration.showNotification()`
  - `tag: 'group_' + groupId` для группировки
  - `renotify: true`
- `notificationclick` → `clients.matchAll()` → focus или `openWindow()` с deep link

### 3.2. `web-push.js`
- `isPushSupported()` — проверка поддержки
- `requestPermission()` — запрос разрешения
- `registerServiceWorker()` — регистрация SW
- `subscribe(reg)` — подписка + отправка на сервер
- `unsubscribe()` — отписка
- `checkSubscriptionStatus(reg)` — проверка существующей подписки
- `init()` — инициализация для авторизованных пользователей

### 3.3. `web-push-suppression.js`
- Page Visibility API — отправка состояния видимости на сервер
- `window.WEB_PUSH_VISIBILITY.setPage(page, groupId)`

## Фаза 4: Интеграция в HTML

Добавить в `profile.html`, `group.html`, `chats.html`, `namahatta.html`, `index.html`:
```html
<script src="/service-worker.js"></script>
<script src="/web-push.js"></script>
<script src="/web-push-suppression.js"></script>
```
После DOMContentLoaded: `WEB_PUSH.init()`

В `group.html`: `WEB_PUSH_VISIBILITY.setPage('group.html', groupId)`
В `profile.html`: `WEB_PUSH_VISIBILITY.setPage('profile.html', null)`

## Фаза 5: Интеграция в существующие API

Все вызовы web push в `try/catch` — не должны ломать основную логику.

| # | Файл | Триггер |
|---|------|---------|
| 1 | `api/send_message.php` | Новое сообщение в чат |
| 2 | `api/update_application_status.php` | Одобрение/отклонение заявки |
| 3 | `api/submit_application.php` | Подтверждение заявки |
| 4 | `api/create_event.php` | Новое событие |
| 5 | `api/send_event_reminders.php` | Напоминание о событии |
| 6 | `api/leave_group.php` | Выход из группы |

Пример интеграции в `send_message.php`:
```php
try {
    require_once __DIR__ . '/send_web_push.php';
    sendWebPushToUser($pdo, $recipientId, $pushTitle, $pushBody, [
        'action' => 'new_group_chat_message',
        'group_id' => (string)$groupId,
        'target_page' => 'group.html',
        'target_params' => json_encode(['id' => $groupId, 'open_chat' => 1])
    ]);
} catch (Exception $e) {
    error_log("Web push error: " . $e->getMessage());
}
```

## Проверка

1. Открыть сайт в Chrome (авторизованным) → проверить консоль на "Web Push subscribed"
2. Проверить запись в `user_web_push_subscriptions`
3. Отправить сообщение в чат → получить push-уведомление
4. Кликнуть на уведомление → открыть `group.html?id=X&open_chat=1`
5. Отправить 5 сообщений в одну группу → показать 1 уведомление (группировка)
6. Открыть Firefox → аналогичная проверка
7. Заблокировать уведомления → graceful fallback без ошибок
8. Проверить уведомления о заявках и событиях
