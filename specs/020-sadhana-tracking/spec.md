# Спецификация: Отслеживание садханы (020-sadhana-tracking)

## Обзор и контекст
Функционал отслеживания садханы позволяет пользователям вести ежедневный учёт духовных практик и режима дня. Пользователь заполняет дневной лог: указывает количество прочитанных книг, пройденные утренние службы, время и длительность джапа-медитации, время служения, а также режим сна (время отбоя и подъёма). Данные сохраняются на сервере с резервным сохранением в localStorage. Пользователь может настраивать карточки практик: добавлять новые, изменять целевые значения, архивировать ненужные.

Приложение должно быть полностью адаптивным и корректно работать как на мобильных устройствах (320–768px), так и на десктопах (1024px+). На мобильных — mobile-first layout с фиксированными элементами навигации. На десктопе — центрированная колонка с увеличенным отступлением по бокам, двухколоночный layout для страницы управления карточками.

## Пользовательские сценарии и сценарии приемки

### Сценарий 1: Авторизация и привязка к профилю пользователя
- **Дано:** пользователь открыл страницу "Моя Садхана" из профиля.
- **Когда:** страница инициализируется.
- **Тогда:** USER_ID должен быть получен из текущей сессии пользователя (из профиля/токена авторизации).
- **И:** все API-запросы должны отправляться с корректным `X-User-Id` текущего пользователя.
- **И:** данные садханы должны загружаться и сохраняться только для авторизованного пользователя.

### Сценарий 2: Ежедневное заполнение дневного лога
- **Дано:** пользователь открыл страницу "Моя Садхана".
- **Когда:** пользователь вводит значения практик (книги, службы, джапа, служение) и режим сна.
- **Тогда:** при нажатии "Сохранить день" данные отправляются на сервер через API.
- **И:** при ошибке сохранения данные резервно сохраняются в localStorage.
- **И:** отображается toast-уведомление о результате.

### Сценарий 2: Отображение прогресса выполнения
- **Дано:** пользователь ввёл значения для практик.
- **Когда:** значения меняются (onchange).
- **Тогда:** прогресс-бар и процент выполнения обновляются в реальном времени.
- **И:** практика считается выполненной, если фактическое значение >= целевого.
- **И:** цвет прогресс-бара меняется: серый (0%) → красный (<50%) → жёлтый (50-99%) → зелёный (100%+).

### Сценарий 3: Управление карточками практик
- **Дано:** пользователь на странице "Управление карточками".
- **Когда:** пользователь вводит название, тип (Количество/Длительность), целевое значение и единицу измерения.
- **Тогда:** при нажатии "Добавить" карточка отправляется на сервер и появляется в списке.
- **И:** пользователь может архивировать карточку (кнопка 🗂).

### Сценарий 4: Отслеживание режима сна
- **Дано:** пользователь открыл страницу садханы.
- **Когда:** пользователь выбирает время отбоя и подъёма.
- **Тогда:** автоматически рассчитывается продолжительность сна.
- **И:** если время подъёма меньше времени отбоя, считается, что подъём на следующий день.

### Сценарий 5: Загрузка данных за текущий день
- **Дано:** пользователь открыл страницу садханы.
- **Когда:** страница инициализируется.
- **Тогда:** загружаются карточки практик с сервера (целевые значения, названия, единицы).
- **И:** загружаются данные за текущий день из localStorage (если были ранее сохранены).

## Функциональные требования

- **FR-201 (Дневной лог практик):** Приложение должно предоставлять интерфейс для ввода и отображения фактических и целевых значений для каждой практики (книги, службы, джапа, служение) с возможностью добавления прочитанных книг.

- **FR-202 (Отслеживание режима сна):** Приложение должно позволять пользователю указывать время отбоя и подъёма, автоматически рассчитывать продолжительность сна и сохранять эти данные на сервер.

- **FR-203 (Управление карточками практик):** Пользователь должен иметь возможность добавлять новые карточки практик с указанием названия, типа (COUNT/DURATION), целевого значения и единицы измерения, а также архивировать существующие.

- **FR-204 (Прогресс-бар и визуальная обратная связь):** Приложение должно отображать прогресс выполнения практик в реальном времени с цветовой индикацией (серый → красный → жёлтый → зелёный) и процентом выполнения.

- **FR-205 (Резервное сохранение в localStorage):** При ошибке сетевого сохранения данные должны автоматически сохраняться в localStorage для последующей синхронизации.

- **FR-206 (API интеграция):** Приложение должно взаимодействовать с серверным API для сохранения/загрузки дневных логов, данных сна и карточек практик.

- **FR-208 (Привязка к пользователю):** Данные садханы должны быть привязаны к текущему авторизованному пользователю. USER_ID должен быть получен из текущей сессии (из localStorage токена или профиля пользователя), а не захардкожен. Все API-запросы должны использовать актуальный ID пользователя.

- **FR-207 (Адаптивный дизайн):** Приложение должно поддерживать responsive layout для мобильных (320–768px) и десктопных (1024px+) устройств. Mobile-first подход: базовые стили для мобильных, медиа-запросы для расширения на десктоп. На десктопе — центрированный контент с max-width, двухколоночный layout для управления карточками.

## Критерии успеха (измеряемые и технологически независимые)

- **SC-405 (Идентификация пользователя):** USER_ID должен быть получен динамически из текущей сессии. При отсутствии авторизации — редирект на страницу входа или отображение модального окна авторизации.

- **SC-400 (Адаптивность):** Интерфейс должен корректно отображаться на всех разрешениях от 320px до 2560px+. На мобильных — single-column layout, на десктопе — центрированная колонка max-width 1200px. Переход между брейкпоинтами плавный, без горизонтального скролла.

- **SC-401 (Время загрузки страницы):** Страница "Моя Садхана" должна полностью отрисоваться и быть интерактивной в течение 1 секунды после открытия.

- **SC-402 (Успешность сохранения):** 100% успешных запросов на сервер должны завершаться с HTTP 200; при любой ошибке (network, 4xx, 5xx) данные сохраняются в localStorage.

- **SC-403 (Точность расчёта сна):** Расчёт продолжительности сна должен быть точным до минуты, включая корректную обработку перехода через полночь.

- **SC-404 (Актуальность прогресса):** Прогресс-бар и процент выполнения должны обновляться в течение 100 мс после изменения любого поля ввода.

## Допущения и границы системы

- Серверный API доступен по адресу, заданному в переменной `API_BASE`.
- Пользователь аутентифицирован; `USER_ID` передаётся в заголовке `X-User-Id`.
- Браузер поддерживает CSS Grid, Flexbox, CSS Custom Properties, `localStorage`.
- **Вне рамок спецификации:** Нативные iOS/Android приложения (есть отдельное Android-приложение), PWA-режим, тёмная тема (есть система тем в основном приложении).
