# Спецификация: Система обмена сообщениями в группах (009-chat-system)

## Обзор и контекст
Чат является основным инструментом ежедневного взаимодействия участников Намахатты. Система должна обеспечивать мгновенную передачу текстовых сообщений внутри группы, хранение истории переписки и корректную интеграцию с системой пуш-уведомлений. Реализация выполняется в гибридном веб-интерфейсе для обеспечения кроссплатформенности и быстрого обновления функционала чата.

## Пользовательские сценарии и сценарии приемки
### Сценарий 1: Отправка и отображение сообщения
- **Дано:** Авторизованный пользователь открыл страницу чата группы `group.html`.
- **Когда:** Он вводит текст и нажимает кнопку «Отправить».
- **Тогда:** Сообщение должно мгновенно появиться в списке сообщений с пометкой «Отправка...» или визуальным индикатором.
- **И:** После успешного ответа от сервера индикатор должен смениться на время отправки.

### Сценарий 2: Получение новых сообщений (Real-time feel)
- **Дано:** Пользователь находится в активном окне чата.
- **Когда:** Другой участник группы отправляет сообщение.
- **Тогда:** Сообщение должно появиться в списке без необходимости ручной перезагрузки страницы пользователем (через механизмы поллинга или веб-сокетов).
- **И:** Фокус чата должен плавно сместиться (прокрутиться) вниз к новому сообщению.

### Сценарий 3: История переписки при входе
- **Дано:** Пользователь открывает чат группы, в которой уже была переписка.
- **Когда:** Страница загружается.
- **Тогда:** Приложение должно загрузить последние 50 сообщений из БД и отобразить их в хронологическом порядке (снизу вверх).

## Функциональные требования
- **FR-901 (Схема данных сообщений):** СУБД должна содержать таблицу `messages` с полями `user_id`, `group_id`, `message_text`, `created_at`.
- **FR-902 (API отправки сообщений):** Бэкенд эндпоинт `api/send_message.php` (POST), принимающий JSON с текстом и ID группы.
- **FR-903 (API получения сообщений):** Бэкенд эндпоинт `api/get_messages.php` (GET), возвращающий массив последних сообщений с данными авторов (имя, аватар).
- **FR-904 (Интеграция с Пушами):** При успешной записи сообщения в БД, сервер должен автоматически инициировать отправку FCM пуш-уведомления всем участникам группы, кроме отправителя (используя логику из фичи 002).

## Критерии успеха (измеряемые и технологически независимые)
- **SC-1101 (Скорость доставки):** Задержка между отправкой сообщения одним пользователем и его появлением у другого (при стабильном интернете) не должна превышать 2 секунд.
- **SC-1102 (UX Навигации):** При открытии чата список всегда должен быть прокручен к самому нижнему (последнему) сообщению.
- **SC-1103 (Автономность уведомлений):** Уведомления о сообщениях должны приходить пользователю, даже если страница чата в данный момент закрыта.

## Допущения и границы системы
- На первом этапе используется механизм Long Polling или Short Polling (интервал 3-5 сек) для обновления сообщений.
- **Вне рамок спецификации:** Редактирование и удаление сообщений, пересылка файлов (кроме фото из галереи, реализованного ранее), индикатор «Печатает...».
