# Спецификация: Инфо-центр и Центр уведомлений (014-info-and-notifications)

## Обзор и контекст
Для создания полной копии оригинального приложения Namahatta необходимо реализовать два важных раздела: «Инфо-центр» (база знаний и инструкций) и «Центр уведомлений» (история всех пушей и системных оповещений пользователя). Эти разделы обеспечивают информационную поддержку пользователей и позволяют отслеживать важные события (одобрение заявок, сообщения), даже если пуш был пропущен.

## Пользовательские сценарии и сценарии приемки
### Сценарий 1: Просмотр базы знаний в Инфо-центре
- **Дано:** Пользователь нажимает на иконку «Инфо» в нижней панели навигации.
- **Когда:** Страница `info.html` загружается.
- **Тогда:** Система должна отобразить список информационных карточек (статей/инструкций), полученных из API.
- **И:** При нажатии на карточку должен открываться полный текст инструкции с возможностью вернуться назад.

### Сценарий 2: Просмотр истории уведомлений
- **Дано:** У пользователя есть новые или старые уведомления (одобрена заявка, новое сообщение).
- **Когда:** Пользователь открывает «Центр уведомлений» (через колокольчик в шапке или отдельную кнопку).
- **Тогда:** Приложение должно показать список уведомлений с иконками типов (✅ одобрено, ❌ отклонено, 💬 сообщение).
- **И:** Непрочитанные уведомления должны быть визуально выделены.

### Сценарий 3: Управление уведомлениями
- **Дано:** В списке есть непрочитанные уведомления.
- **Когда:** Пользователь нажимает «Прочитать все» или кликает по конкретному уведомлению.
- **Тогда:** Статус уведомлений в базе данных должен измениться на «прочитано», а счетчик непрочитанных на иконке — исчезнуть.

## Функциональные требования
- **FR-1401 (API Инфо-центра):** Эндпоинт `api/info_handler.php`, возвращающий массив статей базы знаний.
- **FR-1402 (СУБД Уведомлений):** Таблица `notifications` с полями: `user_id`, `type`, `title`, `text`, `is_read`, `created_at`.
- **FR-1403 (API Уведомлений):** Эндпоинты `get_notifications.php`, `mark_notification_read.php`, `clear_notifications.php`.
- **FR-1404 (Веб-интерфейс):** Страница `info.html` и модальное окно/страница истории уведомлений.

## Критерии успеха (измеряемые и технологически независимые)
- **SC-1601 (Скорость загрузки Инфо):** Время рендеринга списка статей не должно превышать 300 мс после открытия вкладки.
- **SC-1602 (Актуальность счетчика):** Счетчик непрочитанных уведомлений должен обновляться мгновенно после вызова API «прочитать все».
- **SC-1603 (UX уведомлений):** Каждое уведомление должно содержать кликабельную ссылку для перехода к соответствующей странице (например, на страницу чата).

## Допущения и границы системы
- Статьи Инфо-центра хранятся либо в БД, либо в статическом JSON-файле на сервере.
- **Вне рамок спецификации:** Поиск по статьям Инфо-центра (только список).
