# Спецификация: Система заявок на вступление в группу (006-group-applications)

## Обзор и контекст
Процесс вступления в группу в экосистеме Namahatta основан на системе модерации. Пользователи подают заявки через веб-интерфейс, а лидеры групп управляют ими через высокопроизводительный нативный интерфейс в Android-приложении. Это гарантирует, что лидеры могут оперативно реагировать на новых участников, получая уведомления и принимая решения одним нажатием.

## Пользовательские сценарии и сценарии приемки
### Сценарий 1: Подача заявки пользователем (Веб)
- **Дано:** Авторизованный пользователь просматривает страницу группы в WebView.
- **Когда:** Он нажимает кнопку «Подать заявку на вступление».
- **Тогда:** Веб-приложение должно отправить запрос на сервер, создав запись о заявке со статусом «ожидание».
- **И:** Лидер этой группы должен получить мгновенное пуш-уведомление о новом кандидате.

### Сценарий 2: Просмотр списка заявок лидером (Нативный экран)
- **Дано:** Лидер группы получает уведомление о заявке или нажимает кнопку «Заявки» в нативном меню.
- **Когда:** Открывается нативная активность `GroupApplicationsActivity`.
- **Тогда:** Приложение должно загрузить из API актуальный список всех необработанных заявок для всех групп, которыми управляет данный лидер.
- **И:** Отобразить их в виде нативного списка с именами кандидатов и кнопками действий.

### Сценарий 3: Одобрение или отклонение заявки
- **Дано:** Лидер просматривает список заявок в нативном интерфейсе.
- **Когда:** Он нажимает кнопку «Одобрить» или «Отклонить» на карточке кандидата.
- **Тогда:** Приложение должно отправить асинхронный запрос к API для обновления статуса.
- **И:** При одобрении — автоматически добавить пользователя в таблицу участников группы.
- **И:** Удалить карточку из нативного списка с плавной анимацией.

## Функциональные требования
- **FR-601 (Нативный экран управления заявками):** Android-приложение должно содержать активность `GroupApplicationsActivity` с ленивым списком (`LazyColumn`), отображающим активные запросы.
- **FR-602 (Серверный API заявок):** Бэкенд должен предоставлять эндпоинты:
    - `api/apply_to_group.php`: создание заявки (POST).
    - `api/get_applications.php`: получение списка заявок для лидера (GET).
    - `api/process_application.php`: изменение статуса одобрено/отклонено (POST).
- **FR-603 (Схема данных заявок):** База данных должна содержать таблицу `applications` для хранения истории запросов и их текущих состояний.
- **FR-604 (Интеграция пуш-уведомлений):** Серверная часть должна инициировать отправку FCM-пакета лидеру группы при создании новой записи в таблице заявок.

## Критерии успеха (измеряемые и технологически независимые)
- **SC-801 (Скорость обработки):** Время с момента нажатия кнопки «Одобрить» в Android до фактического обновления статуса в БД и получения подтверждения не должно превышать 500 мс.
- **SC-802 (Плавность списка):** Удаление обработанной заявки из нативного списка должно сопровождаться стандартной плавной анимацией (fade-out/slide) без рывков.
- **SC-803 (Точность доставки пушей):** Лидер группы должен получать уведомление о новой заявке в течение не более 5 секунд после её подачи участником.

## Допущения и границы системы
- Лидер группы определяется по полю `leader_id` в таблице `groups`.
- **Вне рамок спецификации:** Написание сопроводительных писем при подаче заявки и просмотр архива отклоненных заявок (только работа с активными).
