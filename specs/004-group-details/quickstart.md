# Руководство по быстрой проверке Деталей группы (quickstart.md)

В данном руководстве приведены сценарии проверки REST API эндпоинта и логики работы нативного экрана.

---

## Тест-кейс 1: Валидация API выдачи данных группы (Критерий SC-602)

Проверка выполняется через curl-запрос для контроля структуры JSON-пакета:

### Шаг 1: Запуск запроса
Выполните GET запрос к развернутому API-скрипту:
```bash
curl -X GET http://localhost/api/get_group_details.php?id=1
```

### Шаг 2: Проверка JSON-пакета данных
- **Ожидаемый результат:** Сервер мгновенно (в пределах критерия `SC-602` — 250мс) возвращает вложенную JSON-структуру, содержащую обязательные узлы: `id`, `name`, `leader` (объект с аватаром), `photos` (массив строк), `members` (массив участников с ролями).

---

## Тест-кейс 2: Проверка нативного экрана через ADB (Критерий SC-603)

Проверка корректности запуска активности и передачи параметров Интента:

### Шаг 1: Эмуляция запуска нативного экрана группы из терминала
Выполните adb-команду запуска `GroupDetailActivity` с тестовым идентификатором группы `id = 1`:
```bash
adb shell am start -n com.example.namahatta/.GroupDetailActivity --ei "groupId" 1
```

### Шаг 2: Проверка интерфейса приложения
- **Ожидаемый результат:** На экране смартфона открывается полноценное нативное окно. Показывается индикатор загрузки, данные успешно скачиваются из API. Рендерится горизонтальный слайдер фото и вертикальный скролл списка участников группы. 
- **Проверка SC-603:** Если вызвать команду с `id = 999` (у которой нет фото), блок `HorizontalPager` должен полностью отсутствовать, верстка должна сместиться вверх без пустых дыр.
