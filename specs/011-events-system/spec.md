# Спецификация: Система управления мероприятиями (011-events-system)

## Обзор и контекст
Мероприятия — это запланированные встречи групп Намахатты или Бхакти-врикши. Система мероприятий позволяет лидерам планировать встречи, указывать время, место и тему, а участникам — просматривать расписание и отмечать свое участие. Реализация охватывает бэкенд API для хранения данных и гибридный интерфейс для отображения списка событий и их деталей.

## Пользовательские сценарии и сценарии приемки
### Сценарий 1: Создание мероприятия (Лидер)
- **Дано:** Авторизованный пользователь является лидером группы.
- **Когда:** Он открывает форму создания мероприятия для своей группы, вводит название, дату, время и описание, затем нажимает «Создать».
- **Тогда:** Система должна сохранить мероприятие в базе данных и привязать его к соответствующей группе.
- **И:** Все участники группы должны получить уведомление о новой запланированной встрече.

### Сценарий 2: Просмотр списка мероприятий участником
- **Дано:** Участник группы открывает раздел «Мероприятия».
- **Когда:** Страница загружается.
- **Тогда:** Система должна отобразить хронологический список будущих мероприятий для всех групп, в которых состоит пользователь.
- **И:** Каждая карточка мероприятия должна содержать название группы, тему встречи, дату и время.

### Сценарий 3: Запись на мероприятие
- **Дано:** Пользователь просматривает детали конкретного мероприятия.
- **Когда:** Он нажимает кнопку «Я приду».
- **Тогда:** Приложение должно зафиксировать его участие в базе данных и обновить счетчик участников на экране.

## Функциональные требования
- **FR-1101 (Схема данных мероприятий):** СУБД должна содержать таблицу `events` (связи с `groups`) и таблицу `event_participants` (связи пользователей с мероприятиями).
- **FR-1102 (API управления событиями):** Бэкенд должен предоставлять эндпоинты:
    - `api/get_events.php`: список будущих мероприятий пользователя (GET).
    - `api/create_event.php`: создание нового события (POST).
    - `api/join_event.php`: отметка об участии (POST).
- **FR-1103 (Веб-интерфейс событий):** Создание страницы `events.html` с календарем или списком предстоящих встреч.
- **FR-1104 (Нативная интеграция деталей):** При клике на мероприятие из списка в Android, приложение может открывать нативный экран деталей (если спроектировано) или детальную веб-страницу.

## Критерии успеха (измеряемые и технологически независимые)
- **SC-1301 (Актуальность данных):** Список мероприятий должен автоматически скрывать прошедшие события через 1 час после времени их окончания.
- **SC-1302 (Скорость отклика API):** Получение списка из 20 ближайших мероприятий не должно занимать более 300 мс.
- **SC-1303 (Точность уведомлений):** Пуш-уведомление о новом мероприятии должно доставляться участникам в течение 10 секунд после создания.

## Допущения и границы системы
- Мероприятия создаются только лидерами групп.
- **Вне рамок спецификации:** Редактирование и отмена мероприятий, напоминания за час до встречи (это фича уведомлений 012), загрузка фотоотчетов после мероприятия.
