# Модель данных: Система Push-уведомлений и FCM (002-push-notifications)

## 1. Структура входящего Push-пакета (Payload Схемы)

Каждое входящее уведомление от сервера бэкенда приходит в формате FCM Data Message (блок `data`), что гарантирует вызов нативного кода `onMessageReceived` в фоновом и в активном режимах работы приложения.

### JSON-структура блока `data` (Payload):
```json
{
  "title": "Новое сообщение в группе",
  "body": "Иван: Приветствую! Завтра встреча в 18:00.",
  "chatId": "125",
  "targetUrl": "https://namahatta.ru/group.html?id=125"
}
```

### Спецификация полей:
- `title` (String): Заголовок для отображения в системной шторке.
- `body` (String): Основной текст сообщения.
- `chatId` (String): Идентификатор чата/группы. Используется нативным контейнером для сверки с активным контекстом экрана под критерий подавления `SC-402`.
- `targetUrl` (String): Абсолютный или относительный URL-путь веб-приложения, на который контейнер обязан переключить WebView при клике пользователя на пуш (Критерий `SC-401`).

---

## 2. Локальная модель кэширования токенов

Нативный контейнер использует легковесное хранилище (`SharedPreferences`) для трекинга состояния синхронизации токена устройства, реализуя отказоустойчивую очередь кэширования под критерий `SC-403`:

```kotlin
data class FcmTokenRegistration(
    val token: String,               // Строка токена, полученная от Firebase
    val isSynchronizedWithWeb: Boolean // Флаг, подтверждающий, что токен успешно ушел в WebView мост
)
```
