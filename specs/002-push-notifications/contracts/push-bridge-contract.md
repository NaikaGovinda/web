# Контракт интерфейса: Расширение Моста Push-Уведомлений

Этот документ расширяет глобальный контракт взаимодействия `window.AndroidBridge` и фиксирует новые сигнатуры вызовов для поддержки системы push-уведомлений.

---

## 1. Вызовы из Android в JavaScript (Исходящие для контейнера)

Вызовы осуществляются нативной оболочкой через `webView.evaluateJavascript()` сразу после генерации токена или после успешного завершения события загрузки страницы `onPageFinished`, если токен был закэширован в оффлайн-режиме (`SC-403`).

### `window.onFcmTokenUpdated(token: String): void`
Передает актуальный токен устройства в веб-приложение.
- **Аргументы:**
  - `token`: Уникальная алфавитно-цифровая строка токена Firebase Messaging.
- **Поведение веб-приложения:** При получении токена веб-код обязан выполнить асинхронный POST-запрос на бэкенд-сервер (например, в API `api/update_user_fcm_token.php`) для привязки этого токена к текущей сессии авторизованного пользователя.

---

## 2. Обновленное поведение существующего контракта `setActiveChat`

Для реализации умного подавления уведомлений (`SC-402`), существующий метод моста `setActiveChat(chatContextJson: String)` (зафиксированный в фиче `001`) связывается со сквозным архитектурным хранилищем приложения.

- Когда веб-приложение вызывает `window.AndroidBridge.setActiveChat('{"activeChatId":"125"}')`, нативный контейнер сохраняет `"125"` в потоковую переменную памяти `MainViewModel.activeChatId`.
- Когда пользователь выходит из чата в главное меню, веб-приложение обязано вызвать `window.AndroidBridge.setActiveChat('{"activeChatId":null}')`, переводя нативный фильтр подавления в неактивное состояние.
