# Спецификация: Нативный экран «Участники группы» (008-group-members)

## Обзор и контекст
Экран «Участники группы» предназначен для удобного просмотра полного состава Намахатты / Бхакти-врикши. Основной акцент сделан на производительности при работе с большими списками и возможности быстрого поиска людей по различным критериям (имя, духовное имя, роль). Данный функционал реализуется в виде нативного Android-компонента для обеспечения мгновенного отклика интерфейса на поисковые запросы пользователя.

## Пользовательские сценарии и сценарии приемки
### Сценарий 1: Переход к списку участников
- **Дано:** Пользователь находится на нативном экране деталей группы (Фича 004).
- **Когда:** Он нажимает на заголовок раздела «Участники» или кнопку «Показать всех».
- **Тогда:** Приложение должно запустить нативную активность `GroupMembersActivity`, передав идентификатор группы `groupId`.
- **И:** Экран должен мгновенно загрузить полный список участников из API.

### Сценарий 2: Поиск по имени или духовному имени
- **Дано:** Открыт экран со списком участников.
- **Когда:** Пользователь вводит текст в поле поиска (например, "Иван" или "Ишвара").
- **Тогда:** Список должен отфильтроваться в реальном времени, отображая только тех пользователей, чье имя или духовное имя содержит введенную строку.
- **И:** Совпадения должны подсвечиваться или быть явно видны.

### Сценарий 3: Фильтрация по ролям
- **Дано:** Список участников открыт.
- **Когда:** Пользователь выбирает фильтр «Помощники».
- **Тогда:** Приложение должно скрыть обычных участников и отобразить только тех, кто имеет роль «помощник» в данной группе.

## Функциональные требования
- **FR-801 (Нативная активность участников):** Наличие экрана `GroupMembersActivity` на базе Jetpack Compose с ленивой загрузкой данных.
- **FR-802 (Компонент поиска и фильтрации):** Интеграция нативного `SearchBar` в верхней части экрана, работающего со стейтом списка в памяти приложения.
- **FR-803 (Серверный API списка участников):** Бэкенд должен предоставлять эндпоинт `api/get_group_members.php?groupId=ID`, отдающий расширенный массив данных участников (включая духовные имена и ссылки на аватары).
- **FR-804 (Визуальная дифференциация):** Разделение участников в списке по ролям с помощью иконок или цветовых меток (например, лидер выделяется короной или яркой подложкой).

## Критерии успеха (измеряемые и технологически независимые)
- **SC-1001 (Скорость фильтрации):** Перестроение списка при вводе каждого символа в поиске должно занимать не более 100 мс (внутри памяти приложения).
- **SC-1002 (Информативность):** Каждый элемент списка должен содержать как минимум: фото, имя, духовное имя (если есть) и роль участника.
- **SC-1003 (Глубина поиска):** Поиск должен выполняться одновременно по двум полям — `name` и `spiritual_name`.

## Допущения и границы системы
- На данном экране недоступно удаление участников (только просмотр и поиск).
- В списке отображаются только пользователи со статусом «одобрено» в таблице участников.
- **Вне рамок спецификации:** Просмотр подробных анкет участников (переход к другим профилям).
