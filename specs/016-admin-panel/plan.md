# Технический план: Глобальная панель администратора (016-admin-panel)

## 1. Архитектура и Безопасность

Админ-панель требует строгой изоляции и проверки ролей на каждом уровне запроса.

### Бэкенд (PHP 8.1+)
- **Middleware:** Реализация `checkAdminAuth()` для защиты всех API в папке `api/admin/`.
- **СУБД:** Манипуляция всеми реляционными связями в таблицах `groups` и `users`.

### Фронтенд (JS/HTML)
- **Страница `admin.html`:** Использование Apple-style карточек для отображения сводной статистики (Dashboard).
- **Списки:** Пагинация или "бесконечный скролл" для управления большим количеством пользователей.

---

## 2. Модель данных доступа

```sql
-- Расширение таблицы пользователей (FR-1603)
ALTER TABLE `users` 
ADD COLUMN `role` ENUM('user', 'admin') DEFAULT 'user' AFTER `avatar_url`;

-- Назначение первого админа для тестов
UPDATE `users` SET `role` = 'admin' WHERE id = 1;
```

---

## 3. Фазы реализации

### Фаза 1: СУБД и Бэкенд API
- Выполнение SQL миграции ролей.
- Реализация `api/get_admin_data.php` (агрегированные данные групп/пользователей).
- Реализация `api/admin_assign_leader.php`.

### Фаза 2: Веб-Интерфейс Админа
- Создание страницы `backend/admin.html`.
- Реализация формы создания группы и поиска пользователей.

### Фаза 3: Верификация
- Тест на запрет доступа обычному пользователю (HTTP 403).
- Проверка функции назначения лидера и обновления нативных экранов.
